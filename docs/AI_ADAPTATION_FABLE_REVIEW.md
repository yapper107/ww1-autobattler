## 2. `PlatoonApproachAllowed` is a permanent veto

Yes. `PlatoonSim.cpp:24-25` returns false for any candidate within 12m of a Support-cause failure objective at the same geometry, and `plan.attempts` persist across replans for the whole battle, so the veto never expires. The squad-level rule is already narrower: `RefusedFinalApproach` (`CognitiveSupport.cpp:38-45`) only blocks while a contact observed within 8s sits within 6m of the failure focus and the failure is unresolved. The platoon should not be stricter than the squad.

**Fix 1: evidence-gated reconsideration.** Replace the unconditional veto with: a Support failure at the same geometry blocks a candidate only while none of the following hold in the commander's knowledge:
- the failure's `threat` track is cleared (`clearedAt > failure.at`) or no longer known, and no contact observed within 8s lies within 6m of `failure.focus`;
- the support squad's reported position now satisfies `CanCoverFocus(support.position, failure.focus)`;
- the mover's report shows `SupportFailureResolved` for that failure (real rounds received at the focus).
Bound reissues to one per failure record (add `bool retried` to `FailedAttempt`, append-only). Aim the Observe fallback at the refused focus rather than the effort contact, so the observation produces the clearance evidence the rule needs. Invariants: no candidate is reissued while the refusing condition is unchanged; a retry is a new directive with the existing preflight gate, so it still requires real delivery before final entry; no hidden enemy state, all inputs are `WithTracks(commander)` and reported support positions. Scenario: refusal at 40s against a durable occupant; at 80s the occupant is removed (health zero) while an observer with line of sight clears the patch by production sensing; assert one new Seize directive within `4*reportDelay+5` of the clearance report, the squad's preflight still demands delivery, and a control where the occupant stays alive but merely unobserved for 30s issues nothing.
